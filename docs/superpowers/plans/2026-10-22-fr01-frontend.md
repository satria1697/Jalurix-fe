# FR-01 Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build usable customer and transport request workflows with the Forest Chocolate theme and browser-local persistence.

**Architecture:** Feature modules expose typed repositories consumed by Pinia stores and Vue views. One versioned localStorage envelope holds both features; a future HTTP repository can replace this adapter. Shared layout, fields, and dirty-form handling keep screens consistent.

**Tech Stack:** Existing Vue 3, TypeScript, Vue Router, Pinia, Tailwind, Vitest, Vue Test Utils; no additional runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-fr01-frontend-design.md`

## Global Constraints

- Go architecture, APIs, authentication, and production persistence are deferred.
- All new requests remain Draft.
- Originating staff is a stable, explicitly labelled `Demo staff` identity.
- Clearly label the application `Local demo — data saved in this browser`.
- Use deep forest green (#183D32), chocolate (#573D2E), cream (#F6F2E9), moss (#82956B), and dark brown (#302B25).
- Preferred schedule values are optional local date/times, explicitly labelled WIB (Asia/Jakarta), serialized as UTC instants.
- Preserve the existing storybook routes.
- No customer deletion, request cancellation, or non-Draft transitions.

## Review Focus

- Corrupted or unavailable storage must preserve existing bytes and show a recoverable error (Task 2).
- Zero, negative, fractional quantities and half-filled coordinate pairs must produce field errors (Task 1).
- Customer edits must not mutate previously copied request addresses (Tasks 2 and 5).
- Failed saves must preserve entered values and keep the editor open (Tasks 4 and 5).
- Leaving an unsaved request to create a customer must preserve the request draft (Task 5).

## Task 1: Domain validation and WIB dates

**Interfaces:** Export `Customer`, `CustomerInput`, `TransportRequest`, `RequestInput`, `CargoItem`, `Location`, `FieldErrors = Record<string, string>`. Inputs omit generated identity/timestamps/status/creator. Customer and request use the fields from the spec; request schedules are optional UTC strings, creator is `{ id: 'demo-staff', name: 'Demo staff' }`, status is `'draft'`. Export `validateCustomer(input: CustomerInput): FieldErrors`, `validateRequest(input: RequestInput): FieldErrors`, `toUtc(wib: string): string`, and `toWib(utc: string): string`. Validation error keys use dotted paths such as `cargo.0.quantity` and `pickup.latitude`.

- [ ] Write failing validation/time tests: trimmed blank customer name fails; optional malformed email fails; permissive phone passes; empty cargo fails; quantity 0, -1, and 1.5 fail; supplied measurements must be positive; coordinate pairs are both required and respect inclusive bounds; delivery preceding pickup fails.

- [ ] Run `npm run test:unit -- --run src/features/customers/__tests__/validation.spec.ts src/features/requests/__tests__/validation.spec.ts src/shared/__tests__/time.spec.ts`; confirm meaningful failures.

## Task 2: Local persistence and repositories

**Interfaces:** `CustomerRepository` exposes `list(): Promise<Customer[]>`, `get(id: string): Promise<Customer | undefined>`, `create(input: CustomerInput): Promise<Customer>`, `update(id: string, input: CustomerInput): Promise<Customer>`. `RequestRepository` has equivalent methods for requests. `createLocalRepositories(storage: Storage)` returns `{ customers: CustomerRepository, requests: RequestRepository }`. Database envelope is `{ version: 1, nextRequestNumber: number, customers: Customer[], requests: TransportRequest[] }`; key is `jalurix.fr01.v1`.

- [ ] Write failing repository tests using injected Storage: round-trip customer/request, unique sequential references (`REQ-000001` onward), crypto IDs, referential validation, unchanged request creator/createdAt on edit, and customer address edits leave request locations unchanged.
- [ ] Test absent key seeds once; a valid empty dataset stays empty. Malformed JSON, invalid nested records, and unsupported versions reject without altering stored bytes. Storage read/write errors reject without changing repository state. Returned objects cannot mutate stored records by reference.
- [ ] Run `npm run test:unit -- --run src/data/__tests__/localRepositories.spec.ts`; confirm failures.
- [ ] Implement database validation, fictional seeds, and async adapters. Each write reads the current envelope, validates input/references, creates an updated copy, writes once, then returns a detached record. Store schedules in UTC. Expose readable storage errors; recovery retries reading and never auto-resets corrupt records.
- [ ] Re-run repository tests; require all passing. Commit data layer and repository interfaces.
